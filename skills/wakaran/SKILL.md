# /wakaran

不慣れな問題空間で判断を求められて手に余るときの入口。目的は「技術の良し悪しの評価」をユーザーに投げないこと。ユーザーが答える問いは自分の状況についての事実だけに限定する。

## 引数

- なし: 手順1の鎖を書き、切れ方からモードを選ぶ
- `A`〜`F`: 鎖は書くが、モードはその記号に固定する
- `寄せて`: モード C に固定する

## 手順1: 鎖を書き、切れ方でモードを決める

ユーザーに症状を聞かない。症状を選ぶこと自体が判断で、不慣れなときはそれができない。

まず次の4行を書く。
1. チケット（または依頼）の目的
2. いまやっている作業
3. 2 が 1 にどうつながるか
4. 終わりの条件

鎖のどこで書けなくなるかでモードを決める。

| 鎖の切れ方 | モード |
|---|---|
| 1 の目的そのものが書けない | B |
| 4行とも書けるが、決めるべき点が複数残る | A |
| 決めるべき点は1つで、候補が複数ある | C |
| 切れる箇所が順序・状態遷移にある | D |
| 4行とも書けていて、すでに決定済み | E |
| 語の意味が分からず鎖が書けない | F |

出力の先頭に「鎖の4行」と「選んだモードと理由（1行）」を置く。ユーザーは読むだけでよく、違うと思えば `A`〜`F` の引数で打ち直せる。

モードの記号:
- A. 縮める
- B. 鎖の切れ目を報告する
- C. 寄せる
- D. 図にする
- E. 批評
- F. 用語

## 手順2: モード別の出力

### A. 縮める
- 決めるべき一点を1つに絞る
- 既定案を1つ出し、それを「選ばない条件」を列挙する
- ユーザーに聞いてよいのは状況の事実だけ（戻せない変更を許すか、確認に半日かける価値があるか、いま壊れるのと後で壊れるのはどちらが嫌か等）。最大1問
- 技術的に決められることはエージェントが決め、「こう決めた / 理由 / 覆す条件」の形で報告する

### B. 鎖の切れ目を報告する
- 手順1で書けなかった行を示し、「作業が目的から漂流している」と報告する
- 元のチケット・依頼の受入条件を引いて、そこから鎖を書き直す

### C. 寄せる
- デファクト（公式ドキュメント、著名書籍の章、フレームワークの既定挙動）を出典つきで既定案にする
- 既定案から外れる点だけ列挙し、各行に理由と、外れなかった場合の帰結を書く
- 「一般的には」「よくある」は禁止。出典を名指しできない主張は [仮定] にする
- デファクトが存在しない論点は「出典なし、推測」と明記する。捏造しない
- デファクトが効くのは技術選択だけ。プロダクトや組織のトレードオフにはデファクトが無く、既定案の捏造を誘うので使わない

### D. 図にする
- シーケンス図か状態遷移図のみ（Mermaid）
- 仕組みの解説図は作らない。効くのは「順序」と「誰に何が起きるか」だけ

### E. 批評（critic）
- ここまでの決定内容を出力ファイル（後述）に落とす
- `critic` agent にそのファイルパスだけを渡す（会話履歴は渡さない）
- 返ってきた指摘をユーザーに示し、採否を出力ファイルに追記する

### F. 用語
- 出てきた語を5つまで、この文脈での意味だけを書く。一般的な定義は書かない

## 全モード共通の約束

- すべての主張に色を付ける
  - [実測]: 動かして確認した
  - [読んだ]: コードや文書の該当箇所を参照した。パスか出典を書く
  - [仮定]: 確認していない
- Pros/Cons 表は作らない。「既定案1つ + 選ばない条件」の形にする
- ユーザーへの状況の問いはモード内の最大1問まで。技術的な選択を聞く問いは禁止。末尾の自己確認2問（後述）は別枠で、回答は任意
- 出力の置き場: プロジェクトの CLAUDE.md に決定ログや検討メモの置き場が書かれていればそこ。無ければ `docs/wakaran/` に、`YYYY-MM-DD-<題材>.md` というファイル名で書く
- `## 学び` の直前に `## 自己確認` を置き、次の2問だけを書く。採点しない。答えられなければ既定案を採用しない、という自己判定のための問い。(1) 既定案を選ばない条件を、自分の言葉で1行にすると何か。(2) [仮定] の行のうち、自分で確認するのはどれか
- 末尾に `## 学び` という見出しで5行以内の学びを書く。出典を1行含め、書籍なら章まで、文書なら URL かパスを書く。次に同じ領域が来たときの足場であり、/catchup がこの節を刈り取る

## やらないこと

- ユーザーに症状やモードを選ばせること（鎖の切れ方から機械的に決める）
- critic の自動起動（E を選んだときだけ）
- 質問の連発
- 仕組みの解説図、ELI5
- 自己確認の採点、理解度テストの出題（diff ベースの理解度確認は quiz-me など既存 skill に任せる）
