# /catchup

/wakaran の末尾に残した「学び」を刈り取り、次に同じ判断を自分でできるようになるための読書リストにする。タスク中ではなく、区切りや終業後に別セッションで実行する。

## 引数

- なし: 決定ログ・検討メモの置き場（プロジェクトの CLAUDE.md に指定があればそこ、無ければ `docs/wakaran/`）配下の、`## 学び` 見出しを持つ Markdown すべて（直近 4 週間の更新分）
- `Nw` / `Nd`: 期間指定（例: `8w`）
- ディレクトリパス: そのディレクトリ配下のみ

## 手順

### 1. 収集（読み取り専用の subagent に委譲）
- 対象ファイルから `## 学び` 節を抜き出す。ファイルパスと更新日を添える
- 主セッションでは Grep/Glob を使わず、読み取り専用の subagent（Explore など）に「パス・更新日・学び節の本文」だけ返させる

### 2. 集計
- 学びをトピックに束ねる（例: 「ロック待ちとコネクションプールの関係」「ORM の版管理」）
- 再発回数順に並べ、上位 3 トピックに絞る。同数なら更新日が新しいものを優先
- 再発 3 回以上のトピックは先頭に ⚠ を付ける。同じ混乱で skill を繰り返している合図で、読む番が来ている
- 各トピックに、元になった学びのファイルパスを列挙する

### 3. 候補探し（WebSearch が使える subagent に委譲。軽量モデルで足りる）
各トピックについて次を集める。
- 書籍: 1 冊、章まで指定。優先順位は 利用者の応答言語で書かれた書籍 → その言語への翻訳書 → 英語原著
- 記事: 1 本。公式ドキュメント → フレームワーク作者・メンテナの記事 → その他
- 目安時間（章1つで何時間か）
- 「読んだら何が判断できるようになるか」を1行。これは必須。「知識が増える」ではなく「次にどの判断を自分でできるか」で書く

### 4. 実在確認（同じ subagent に続けて行わせる）
- 書籍は出版社ページか大手書店サイトを WebSearch で当て、書名・著者・出版社・出版年を照合する
- 照合できたものだけ [読んだ] とし、URL を添える
- 照合できないものは載せない。代替が見つからないトピックは「書籍: 確認できる候補なし」と書く
- 記事は URL の実在を確認する（WebFetch で 200 が返ること）

### 5. 出力
- 決定ログ・検討メモの置き場直下の `catchup.md` に追記する（無ければ作成）
- 先頭に実行日の見出し `## YYYY-MM-DD` を置き、前回分は残す
- 各トピックの形式:

```
### <トピック名>（再発 N 回）
元: <パス1>, <パス2>
読んだら: <何が判断できるようになるか>
書籍: <書名>（著者、出版社、年）第 N 章 [読んだ] <URL> / 目安 N 時間
記事: <タイトル> <URL> / 目安 N 分
```

- 末尾に「今回載せなかったトピック」を名前だけ列挙する（次回の判断材料）

## 約束

- 上位 3 トピックを超えて載せない。リストが長いと読まない
- 書名・著者・翻訳の有無を推測で書かない。確認できなければ載せない
- 主セッションでの WebSearch / WebFetch は行わず、subagent に委譲する
- 委譲先への出力制約: 「トピックごとに確認済みの候補と URL、確認できなかった候補の理由、1500字以内」
