# wakaran

AI エージェントに実装や設計を任せていると、自分が扱い慣れていない領域の判断を求められる場面が増える。
「ロック待ちの上限は 2 秒と 3 秒のどちらにしますか」と聞かれても、答える材料が手元にない。
説明を頼めば流暢な解説が返ってくるが、読み終えても判断できるようにはならない。
分かっていないのは解説の内容ではなく、自分が何を決めさせられているのかだからである。

wakaran は、この状態を扱うための Claude Code plugin である。
判断そのものを肩代わりするのではなく、判断を「自分の状況についての事実の問い」に組み替える。
状況の問いなら、領域に不慣れでも答えられる。

部品は三つある。

- **`/wakaran`**：目的、作業、つながり、終わりの条件の4行を書き、書けなくなった場所からモードを決めて、判断を縮める
- **`/catchup`**：`/wakaran` が残した学びを集計し、繰り返している穴を読書リストに変える
- **`critic`**：決定メモ1本だけを読んで矛盾と抜けを指摘する agent

## 使いどころと使いすぎ

効く場面が狭い道具である。
外れた使い方をすると、判断を縮めるどころか、もっともらしい既定案を鵜呑みにする経路になる。

- 一つの混乱につき一回で終える。出力を読み、状況の問いに答え、動く。
- 同じ場所で二回目を打ちたくなったら、それは混乱ではなく知識の穴である。`/catchup` に回す。`/catchup` が ⚠ を付けたトピックは、この道具で繰り返すのをやめて読む番が来ている合図になる。
- モード C「寄せる」は技術選択にだけ効く。プロダクトや組織のトレードオフにはデファクトが存在せず、そこで既定案を求めると根拠のない標準が捏造される。
- 出力に付く確認度の印（実測、読んだ、仮定）は、どこから確認すべきかの優先順位であって、正しさの保証ではない。「読んだ」もエージェントの自己申告である。
- 既定案だけ読んで「選ばない条件」を読まない。これが一番起きやすい誤用で、判断を縮めた意味が消える。
- 目的が書けないという判定（モード B）が出たとき、モード A に切り替えて押し切らない。縮めた先が目的からずれている。
- 自分の混乱を整理する道具であり、他人との議論に持ち込んで決着をつける道具ではない。
- 出力末尾の自己確認二問に答えられないときは、既定案を採用しない。

## `/wakaran` が出力するもの

### 鎖の4行

最初に次の4行を書く。

1. チケットまたは依頼の目的
2. いまやっている作業
3. 2 が 1 にどうつながるか
4. 終わりの条件

利用者に「何が分からないか」は聞かない。
症状を選べること自体がある種の理解を前提にしており、不慣れなときはそれができない。
代わりに、4行のどこで書けなくなるかを見る。

| 鎖の切れ方 | モード |
|---|---|
| 1 の目的そのものが書けない | B. 鎖の切れ目を報告する |
| 4行とも書けるが、決めるべき点が複数残る | A. 縮める |
| 決めるべき点は一つで、候補が複数ある | C. 寄せる |
| 切れる箇所が順序や状態遷移にある | D. 図にする |
| 4行とも書けていて、すでに決定済み | E. 批評 |
| 語の意味が分からず鎖が書けない | F. 用語 |

選んだモードと理由を1行で示すので、違うと思えば `A`〜`F` の引数で打ち直せる。

### 既定案と選ばない条件

Pros/Cons の表は作らない。
比較表は、評価軸を持っている読者にしか読めない。
代わりに**既定案**を一つ出し、それを**選ばない条件**を列挙する。
利用者の仕事は「選ばない条件が自分の状況に当てはまるか」の確認になり、これは技術の問いではなくなる。

モード C では、既定案は出典付きのデファクト（公式ドキュメント、著名書籍の章、フレームワークの既定挙動）に限る。
「一般的には」という言い方は使わず、出典を名指しできない主張には「仮定」の印を付ける。
デファクトが存在しない論点は、そう書く。

### 確認度の印

出力中のすべての主張に、次のどれかを付ける。

- **実測**：動かして確認した
- **読んだ**：コードや文書の該当箇所を参照した。パスか出典を添える
- **仮定**：確認していない

利用者が読むのは「仮定」の行だけでよい。

### 状況の問いと自己確認

利用者への問いは、モード内で最大一つに限る。
聞くのは「戻せない変更を許すか」「確認に半日かける価値があるか」のような状況の事実で、技術的な選択は聞かない。

末尾に自己確認の二問を置く。
既定案を選ばない条件を自分の言葉で一行にすると何か、そして「仮定」の行のうち自分で確認するのはどれか。
採点はしない。
答えられなければ既定案を採用しない、という自己判定のための問いである。

### 学び

出力ファイルの最後に、5行以内の学びと出典を一行残す。
`/catchup` がこの節を刈り取る。

## `/catchup` と `critic`

**`/catchup`** は、決定メモの置き場にある学びの節を横断して集計する。
トピックを再発回数順に並べ、上位三つに絞り、それぞれに書籍一冊（章まで）と記事一本を付ける。
書籍は出版社ページか大手書店サイトで実在を確認できたものだけを載せる。
各トピックには「読んだら何が判断できるようになるか」を一行で添える。
読む動機を知識の増加ではなく、次に同じ判断を自分でできることに置くためである。
再発三回以上のトピックには ⚠ が付く。

**`critic`** は、ファイル一本だけを渡して矛盾、抜け、pitfall を指摘させる読み取り専用の agent である。
会話履歴を持たないので、主セッションの流れに引きずられない。
代案は出さず、各指摘に確認度の印と「無視したら何が起きるか」を添えて、全体を1000字以内に収める。
`/wakaran` のモード E から呼ばれるほか、決定メモを確定させる前や ADR（Architecture Decision Record）を Accepted にする前の関門として使える。

## インストール

試用は、このディレクトリを直接指定する。

```
claude --plugin-dir /path/to/wakaran
```

導入は marketplace 経由で行う。

```
claude plugin marketplace add ug23/wakaran
claude plugin install wakaran@wakaran
```

## 使い方

正式名は `/wakaran:wakaran` と `/wakaran:catchup` で、他に同名の skill が無ければ短縮形で呼べる。

- `/wakaran`：鎖を書いてモードを選ぶ
- `/wakaran 寄せて`：モード C に固定する
- `/wakaran A`：モードを記号で固定する（`A`〜`F`）
- `/catchup 8w`：直近8週間分の学びを集計する
- `critic` は単独では呼ばない。`/wakaran` のモード E から、または決定メモを確定させる前に `wakaran:critic` として呼ぶ

出力先は、プロジェクトの CLAUDE.md に決定ログや検討メモの置き場が書かれていればそこ、無ければ `docs/wakaran/` である。

## 設計の背景

不慣れな領域で「この二案のどちらが良いか」と聞かれると、聞かれた側は判断材料がないまま選ぶことになる。
説明を足しても解決しない。
解説が流暢であるほど、人間が下書きしたときに感じる「ここが薄い」という違和感が消え、判断できていないことに気づきにくくなる。
wakaran が技術の良し悪しの評価を利用者に投げないのは、この理由による。

症状を選ばせないのも同じ筋である。
最初の版では「何を判断させられているか分からない」「選択肢は分かるが選べない」のような症状を一問で選ばせていた。
試したところ、どれに当たるか分からないという感想が返ってきた。
症状を選ぶこと自体が判断だったからである。
鎖の切れ方で決める方式は、その置き換えである。

学びを刈り取る出口を持たない補助輪は、同じ混乱を何度も繰り返す。
`/wakaran` の学びの節と `/catchup` は、この道具が対症療法で終わらないための仕組みで、繰り返しの多いトピックを読書に変える。
補助輪はいずれ外すものである。
`/catchup` の ⚠ が増えなくなったら、その領域では外してよい。
